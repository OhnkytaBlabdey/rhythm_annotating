# WDS 音符格式依据

渲染参考：<https://github.com/OhnkytaBlabdey/wdschart-render>，核对版本
`4e90935d738aa9c1cd26f9e7150ea65cde25fd67` 的 `render_chart_beat_count.py`。

真实 TXT 谱例：<https://github.com/SonolusHaniwa/sirius-decrypted-data>，核对版本
`9d876d6b99151898a6773566137f2a478bb35bee`。以下外部链接沿用来源仓库的实际名称。

## TXT 记录

无表头的七列 CSV：

```text
start,end,type,lane,width,gimmickType,gimmickValue
```

时间单位为秒。编辑器对点记录输出 `end=-1`，对长条输出结束秒数。
轨道从 1 开始，共 12 列，`width` 是连续占用的列数。

## 编码和渲染

下表描述参考实现实际处理的记录，不将每一个编码推断为新的游戏键种。

| 编码 | 参考渲染行为 |
| --- | --- |
| 10、82 | 粉色普通键 |
| 20、81、83 | 橙色重击键 |
| 80、200 | 蓝键 |
| 30、31 | 蓝色、紫色星形 Sound |
| 40 | 紫色 Scratch，带方向箭头 |
| 50 | 紫色 Flick，带方向箭头和中间横线 |
| 100、101 | 蓝色长条，末端按 80 渲染 |
| 110、111 | 紫色长条，末端按 40 渲染，并应用该区间的 gimmick |
| 900 | 空心矩形长条判定 |

源码位置：分类 567–576 行，长条和末端 698–735 行，Sound 788–800 行，
普通键外观 818–827 行，判定 859–881 行，划键 885–930 行。

参考实现没有将 100/101 或 110/111 渲染为不同的长条外观，
也没有提供这两组编码差异的完整游戏语义；不能仅凭编码推导额外键种。
**长条记录只有身子和尾巴，不包含头键。** 起点可以放独立的键，其类型、范围、
选择、移动、删除和导出都独立于长条。长条起点只是一处时间位置，不占用一个头键。
编辑器不根据 100/101/110/111 自动推断或生成 80/81/82/83。
长条末端由渲染器生成，编辑器不重复导出末端记录。

## gimmick

参考实现 889–908 行同时接受数字字符串和名称：

- `0`：双向箭头；保留原范围，忽略 `gimmickValue`。
- `1` / `JumpScratch`：值是带符号的覆盖宽度。设原始轨道为 L、宽度为 W、值为 V：
  - V > 0：向右，覆盖 `[L, L+V-1]`。
  - V < 0：向左，覆盖 `[L+W+V, L+W-1]`。
  - 编辑器中的尾巴必须覆盖整个身子，范围在 1–12 内。
    只有 `abs(V) > W` 时才保留 JumpScratch；收回到身子范围时清为 `gimmickType=0,gimmickValue=0`，无方向。
- `2` / `OneDirection`：0 为左，非零为右；轨道和宽度不变。

**JumpScratch 是长条尾部属性，不是独立绘制类型，也不决定身子的放置。**
蓝条和紫条的 JumpScratch 都作用于尾部；编辑器通过尾部属性表单及尾巴的左右宽度柄编辑，
保持身子的类型、位置、宽度和时间不变。
参考渲染器也接受携带这些字段的原始 40/50 点记录，读取时保留其范围解释；
这不能作为增加独立 JumpScratch 摆放工具的依据。
分轨/淡入淡出是参考实现的独立图形层，当前编辑器尚未建模这类特效记录。

### 画布编辑

- 蓝/紫长条：第一次点击身子起点，第二次点击更晚的结束拍；头键单独放置。
- 第二次点击只决定结束拍，不因鼠标横向位置创建或改变 JumpScratch。
- 编辑模式下悬停音符显示左右宽度柄，无须先选中：左柄改变左边缘，右柄改变右边缘，
  两边都能向外扩展或向内缩短，并可越过另一端继续反向调整。
  拖动只调整宽度，不改变时间；经过固定端时最小一列，范围 1–12。
- 长条身子的左右柄改变身子宽度；独立头键不随之变化。
- 蓝色、紫色长条尾巴的左右柄都修改尾部 JumpScratch 属性，身子的列和宽度、开始及结束拍都不变。
  左柄以身子右缘为固定端、修改负的覆盖宽度；右柄以身子左缘为固定端、修改正的覆盖宽度。
  拖入身子范围时，尾巴停在身子宽度并清除属性与方向箭头；拖过另一端后，向反方向延伸并重新添加 JumpScratch。
- 拖尾部中央只调整结束拍；宽度及 JumpScratch 保持不变。
- 拖动实时预览，松开保存为一次可撤销操作。越过 1–12 列会被拒绝；Esc 可取消。
  浏览模式保持只读。
- Scratch（40）、两种 Sound（30/31）位于长条身子上时，放置、预览及保存的起始列和宽度
  与身子一致。调整身子或这些内部键的宽度时一起更新；移动身子时携带内部键，独立头键仍独立。
  已有 JumpScratch 尾巴同时改变宽度，保留额外延伸格数和方向：
  `新尾宽 = 新身宽 + (旧尾宽 - 旧身宽)`。画布预览、拖拽保存和属性表单使用同一规则。
  例如身宽 3、尾宽 5，拖宽 Sound 使身宽变为 4 时，尾宽随之变为 6。
  关联由时间区间和所在身子范围推导，重叠时优先匹配相同范围及最近起点，不增加存储字段或版本。
- 绘制区仅保留键种按钮：80、81、82、83、101、111 默认折叠在「少用键种」，其余直接显示。
  不显示新音符宽度属性、原始编码说明或放置提示；属性表单仅在查看已有选中音符时显示。

## 编辑器内部数据

- `chartKind: "wds"`、`ChartNote.wds`、`wdsOffset`。沿用原有存储标记，不提升版本号。
- `wds.gimmickType` / `wds.gimmickValue` 对应 TXT 最后两列。
- 每个头键是独立 `ChartNote`；长条属性中没有头键类型字段。
- `autoTicks` 是显式的编辑器辅助选项，默认关闭。参考渲染器读取实际 900 记录，
  不从长条长度推算半拍判定。开启辅助选项时，导出会明确提示其生成行为。
- `head` 是当前记录的开始拍分数，不是头键。`head` / `tail` / `body` 是内部音乐拍分数；导出沿完整 BPM 时间映射换算秒数，
  仅叠加 `wdsOffset`。`body` 锚点不隐式变成判定。
- TXT 是有损输出；内部 JSON / 项目文件保留 BPM、拍分数、ID 和辅助选项。

### 已有快照恢复

应用版本保持 `0.2.0`。恢复和导入先读取已有存储布局，再验证当前模型。原有布局把音符属性放在
`note[chartKind]` 下，把导出偏移放在 `lane[chartKind + "Offset"]` 下；
读取时将这些存储字段规范化为 `wds`、`wdsOffset` 和当前 gimmick 字段。
旧快照中错误分组的头键在读取时拆成独立点记录，保留长条 ID 和原有头键编码；
已有同位置同编码点记录时不重复添加。后续编辑和导出使用独立记录模型。
转换不修改输入快照，保留拍分数、BPM、标注和判定设置；
已有等宽或比身子窄的 JumpScratch 在读取时恢复为无方向的普通尾巴；后续保存和 TXT 导出不保留冗余属性。
验证通过并恢复成功后，自动保存才写入规范化的数据。未知格式和无效内容仍会报错，
原快照继续由恢复保护机制保留。
